# Viewer

**▶ Published: https://ethical-tech-colab.github.io/williamsburg-bridge-3d/**

A minimal, config-driven browser viewer for source-governed GLB digital twins. Nothing about the
Williamsburg Bridge is compiled into it — swap `public/model.config.json` and it will render another
model built to the same contract.

```bash
npm install
npm run dev        # http://localhost:5175
npm run build      # typecheck + production build into dist/
npm run typecheck
```

**Port 5175 is this bridge's.** The sibling repos run alongside it — `manhattan-bridge-3d` on 5173
and `brooklyn-bridge-3d` on 5174 — so each owns a fixed port and `strictPort` makes a collision fail
loudly. Without that you get the confusing failure of loading a URL and being shown a different
bridge; check the title bar, which always names the model it loaded.

## Deployment

`.github/workflows/pages.yml` rebuilds the model from `GEOMETRY-CONTROL.md`, verifies the committed
artifacts match that rebuild, runs both validation suites, and only then builds and publishes. The
site cannot be updated with geometry that fails its own tests.

`base: './'` in `vite.config.ts` and document-relative URL resolution in `src/model.ts` are what let
one build work at a domain root, under a project-pages subpath, and co-served inside a district
site. Both layouts were verified before the first deploy.

## Full screen

The **Fullscreen** button, or the `f` key, takes the whole document fullscreen — panels included.
That is deliberate: the provenance tally and the metadata locus are part of reading this bridge
honestly, not chrome to be discarded for a prettier picture. Escape leaves.

The dev server needs `public/control_skeleton.glb` and `public/parts.json`, both written by
`python scripts/build_control_skeleton.py` from the repository root. If the page reports that it
could not load the model, run that first.

## What it must do, and why

These are not preferences. They are the rules from `CONFIDENCE-MODEL.md` §4 that stop a
provenance-tagged schematic from lying, and each is implemented here rather than in a side panel.

| Rule | Where |
|---|---|
| `DOCUMENTED` solid, `INFERRED` dashed outline, `ASSUMED` dotted | `src/BridgeViewer.tsx`, `OUTLINE_DASH` |
| The provenance filter **hides**, it does not fade | `src/BridgeViewer.tsx`, the visibility effect |
| No dimension annotated on non-documented geometry — shown as `withheld` | `components/MetadataPanel.tsx` |
| A standing tally, permanently on screen | `components/ConfidenceLegend.tsx` |
| Locus on selection: the controls, grades, sources and open questions behind a part | `components/MetadataPanel.tsx` |
| Materials come from the control document, never the renderer | assigned in the build, baked into the GLB material names |

When every provenance filter is off, the viewer says so in words rather than showing a blank canvas
and letting the reader assume a loading failure.

## Two traps this file exists to record

**Dashed lines need `computeLineDistances()`.** Without it `LineDashedMaterial` renders solid, with
no warning, and the `INFERRED` and `ASSUMED` outlines become indistinguishable from `DOCUMENTED`
ones — silently defeating the entire rendering discipline.

**glTF line primitives load as `LineSegments`, not `Mesh`.** The first version of this viewer
registered only `THREE.Mesh` objects while traversing the loaded scene. Every line-based part — all
four suspender sets, the floor beams, the railings and the whole reference frame — was therefore
invisible to both the provenance filter and the raycaster. It looked like it worked, because the
towers, cables and anchorages *are* meshes and did hide correctly. Line geometry also needs an
explicit `raycaster.params.Line.threshold` before it can be picked at all.

## Files

```
index.html
src/main.tsx              entry point
src/App.tsx               layout, filter state, census
src/BridgeViewer.tsx      three.js scene, provenance rendering, picking
src/model.ts              types, config loading, document-relative URL resolution
src/styles.css
components/Toolbar.tsx           system and provenance filters
components/ConfidenceLegend.tsx  the standing tally
components/PartTree.tsx          component tree explorer
components/MetadataPanel.tsx     locus on selection
public/model.config.json  how to render provenance and confidence
public/control_skeleton.glb, public/parts.json   generated by the build
```

`public/` is the published contract surface: asset URLs in the config are document-relative, so one
build works both standalone and co-served under a district site root.
